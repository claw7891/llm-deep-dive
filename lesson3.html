Training & Pretraining

Training objectives, data pipelines, training dynamics, and compute budgets

Pretraining an LLM is the largest engineering effort in machine learning. A single training run on a 70B-parameter model consumes thousands of GPUs for months, costs tens of millions of dollars, and processes trillions of tokens. Understanding the training process is essential for knowing what these models actually learn — and what they miss.
TL;DR

LLMs are trained on trillions of tokens of internet text using next-token prediction (autoregressive language modeling). The loss is cross-entropy between predicted and actual next token. Training uses distributed data parallelism across thousands of GPUs, AdamW optimizer with cosine learning rate schedule, and gradient clipping. Data quality matters as much as quantity — deduplication, filtering, and curation are critical.

Pretraining Objectives

Autoregressive / Causal Language Modeling

The dominant objective for generative LLMs (GPT, LLaMA, etc.). Given a sequence of tokens x₁, x₂, ..., xₙ, maximize the probability of each token given all previous tokens:

Autoregressive LM Objective
L = −Σt=1T log P(xt | x1, x2, ..., xt−1)

This is simply the negative log-likelihood of the entire sequence under the model. Minimizing this loss is equivalent to maximizing the probability the model assigns to the training data.

Masked Language Modeling

Used by BERT and other encoder-only models. Randomly mask 15% of tokens and predict them from bidirectional context:

L = −Σt ∈ masked log P(xt | x≠t)

Data Curation Pipeline

Raw internet text is noisy, duplicated, and often low-quality. Modern pretraining pipelines apply extensive filtering:

DeduplicationRemove near-duplicate documents (MinHash LSH), duplicate n-gram sequences
Quality filteringHeuristic rules (perplexity thresholds), classifier-based (fastText, CCNet), domain filtering
ToxicityBlocklist URLs, hate speech classifiers, PII redaction
Data mixingWeighted sampling: web text + books + code + academic papers

The LLaMA 3 dataset (15T+ tokens) was curated by training a small language model to score document quality and filtering based on those scores. High-quality data (books, academic papers) is upsampled; low-quality web text is downsampled or discarded.

Training Optimization

Optimizer: AdamW

AdamW is the standard optimizer for LLM training. It combines momentum (for fast convergence) with adaptive learning rates (for handling sparse gradients) and decoupled weight decay:

AdamW Update (per parameter θ)
mt = β₁ · mt−1 + (1 − β₁) · gt   (biased first moment)
vt = β₂ · vt−1 + (1 − β₂) · gt²   (biased second moment)

m̂t = mt / (1 − β₁ᵗ)   (bias correction)
v̂t = vt / (1 − β₂ᵗ)   (bias correction)

θt = θt−1 − η · m̂t / (√v̂t + ε) − λ · η · θt−1

Typical hyperparameters: β₁ = 0.9, β₂ = 0.95, ε = 10⁻⁸, weight decay λ = 0.1

Learning Rate Schedule: Cosine Decay

The learning rate follows a cosine curve: linear warmup from 0 to max_lr over the first ~2,000 steps, then cosine decay to ~10% of max_lr over the remaining steps:

η(t) = ηmax · ½(1 + cos(π · t / T))   (after warmup)

This schedule allows the model to "settle" into a good minimum — high LR early for fast exploration, low LR later for fine-grained convergence.

Batch Size Scaling

LLM training uses very large batch sizes (millions of tokens per batch) and scales the learning rate with batch size according to empirical heuristics:

η(B) = ηref · √(B / Bref)   (or linear scaling for small batches)

LLaMA 2 70B trained with a batch size of 4M tokens across 2,000 GPUs. Each step processes 4M tokens, and the model saw 2T tokens total → 500,000 training steps.

Compute Budget

Training compute is measured in FLOPs (floating-point operations). For a forward and backward pass on a single token with a dense transformer:

Ctrain ≈ 6 · N · D

Where N = number of parameters, D = number of training tokens. The factor 6 comes from: ~2 FLOPs/parameter/token for forward pass + ~4 FLOPs/parameter/token for backward pass.

Distributed Training

Training a 70B model requires more memory than a single GPU can hold. Three levels of parallelism are combined:

  • Data parallelism — each GPU processes different micro-batches, gradients are averaged all-reduce
  • Tensor parallelism — individual matrix multiplies are split across GPUs (Megatron-LM style)
  • Pipeline parallelism — different layers are assigned to different GPUs (GPipe/1F1B style)
ZeRO (Zero Redundancy Optimizer): An optimization that shards optimizer states, gradients, and parameters across GPUs, eliminating redundant copies. ZeRO-3 enables training 100B+ models on thousands of GPUs with near-linear scaling efficiency.

Convergence & Loss Curves

During training, the loss decreases following a power law with the number of tokens seen. A typical training run shows smooth decay with occasional spikes from data quality issues or numerical instability:

Scaling relationship during training
L(D) ≈ L∞ + A · D−α

Where:
L(D) = loss after D tokens of training
L∞ = irreducible loss (entropy of natural language)
A, α = constants (α ≈ 0.1-0.3 for most LLMs)

Gradient clipping (|g| ≤ 1.0), learning rate warmup, and skipping problematic batches all help maintain stable training curves.
