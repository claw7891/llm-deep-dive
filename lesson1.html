Tokenization & Embeddings

How raw text becomes vectors that transformers can process

Before any attention happens or any parameter is updated, raw text must be converted into numerical form. This step — tokenization — is deceptively consequential: it defines the model's vocabulary, affects its ability to handle rare or unseen words, and can introduce subtle biases. Understanding the tokenizer is often the first diagnostic step when an LLM behaves unexpectedly.

The Tokenization Pipeline

Every LLM processes text through this pipeline:

Text → Tokens → Token IDs → Embeddings → Model Input

Subword Tokenization

Modern LLMs don't tokenize by words (too many), characters (too long), or whitespace (misses morphology). Instead they use subword tokenization — breaking text into the most frequent character sequences in the training data.

Byte-Pair Encoding (BPE)

Used by GPT models. The algorithm iteratively merges the most frequent byte pair:

  1. Start with individual characters/bytes as the vocabulary
  2. Count all adjacent pairs in the training corpus
  3. Merge the most frequent pair into a new token
  4. Repeat until desired vocabulary size is reached (e.g., 50k, 100k)
BPE Merge Example
Corpus: "low low low low low lowest lowest lowest wider wider wider"

Step 1: l o w (3 tokens) + whitespace
Step 2: "lo" is most frequent pair → merge → token: lo
Step 3: "low" is most frequent → merge → token: low
Step 4: "lowest" = low + est → merge → token: lowest
Step 5: "wider" = wid + er → merge → token: wider

Result: Vocabulary = {l, o, w, e, s, t, i, d, r, lo, low, est, lowest, wid, er, wider}

WordPiece (BERT)

Similar to BPE but merges pairs that maximize the likelihood of the training data under a language model, rather than by raw frequency:

score(x, y) = P(xy) / (P(x) · P(y))

Where P(x) is the unigram probability of token x. Pairs that appear together more often than expected by chance get merged.

SentencePiece (LLaMA, Gemma)

Treats the input as a raw byte stream (no pretokenization needed), allowing it to handle any Unicode character, digit, or whitespace without language-specific preprocessing. Often uses the Unigram language model objective for segmentation.

Vocabulary Size & Compression

Vocabulary size is a key architectural decision that impacts both model quality and efficiency:

GPT-2BPE50,257~3.5 chars/token
BERTWordPiece30,522~4.0 chars/token

GPT-4cl100k_base (BPE)100,256~4.0 chars/token

Compression ratio — characters per token — measures how efficiently the tokenizer packs information. Higher compression means fewer tokens for the same text, which reduces sequence length and thus attention computation cost (which scales O(L²)).

Tokenization artifacts: BPE can split unexpected words in ways that affect model performance. For example, "cowboy" might be tokenized as "cow" + "boy" (which is sensible) or "c" + "owboy" (problematic). Words seen fewer times in training get fragmented more, which is why LLMs struggle with unusual names, technical jargon, and code.

Token Embeddings

After tokenization, each token ID is mapped to a dense vector via an embedding matrix E ∈ ℝV×d, where V is vocabulary size and d is the embedding dimension (typically 768–8192).

xi = E[ti]

The embedding matrix is learned from scratch during pretraining. Each row of E is a trainable parameter representing one token in d-dimensional space. Semantically similar tokens (e.g., "king" and "queen") end up with similar vectors — the model learns this organically from co-occurrence patterns in text.

Embedding arithmetic: The classic example is king − man + woman ≈ queen. While less clean for subword tokenizers, high-quality embeddings still encode rich semantic relationships in their vector geometry.

Positional Encodings

Self-attention is permutation-invariant: Attention(Q,K,V) processes all tokens identically regardless of order. We must inject position information explicitly.

Sinusoidal (Original Transformer)

Positional Encoding Formula
PE(pos, 2i) = sin(pos / 100002i/d)
PE(pos, 2i+1) = cos(pos / 100002i/d)

Each position gets a unique encoding. Different dimensions have different frequencies, allowing the model to attend to relative offsets rather than absolute positions.

RoPE (Rotary Position Embedding)

Used in LLaMA, Mistral, Gemma. Instead of adding positional vectors, RoPE rotates the query and key vectors by an angle proportional to position:

qi ← R(θ · pos) · qi   kj ← R(θ · pos) · kj

The dot product qi · kj then naturally encodes relative position — the attention score depends only on the offset i − j, not absolute positions. This lets models generalize to longer sequences than they were trained on.

ALiBi (Attention with Linear Biases)

Instead of modifying embeddings, ALiBi adds a bias to attention scores based on the distance between tokens:

score(qi, kj) = qi · kj − m · |i − j|

Where m is a head-specific slope. Simpler than RoPE, used in BLOOM and some MPT models.

Summary

The journey from text to model input involves:

  • Subword tokenization (BPE, WordPiece, SentencePiece) balancing vocabulary size and compression
  • Token IDs mapped through a learned embedding matrix to dense vectors
  • Positional encodings (sinusoidal, RoPE, ALiBi) injecting sequence order information
  • The resulting d×n tensor (n tokens, d dimensions) is the transformer input
