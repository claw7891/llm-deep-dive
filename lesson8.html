Modern Architecture Variants

Beyond the vanilla transformer — MoE, GQA, RoPE, Mamba, FlashAttention

The original 2017 transformer has been modified extensively in every modern LLM. Mixture of Experts scales to trillions of parameters without proportional compute cost. Grouped-Query Attention slashes the KV cache. FlashAttention makes attention IO-aware rather than compute-bound. And Mamba challenges the dominance of attention itself with state space models. These innovations, not raw scale, are what differentiate GPT-4 from its predecessors.
TL;DR

Key innovations beyond the vanilla transformer: (1) Mixture of Experts — activate only a subset of FFN parameters per token, enabling 1T+ total parameters at 100B-level compute; (2) Grouped-Query Attention — fewer KV heads than query heads, slashing KV cache by 4-8×; (3) FlashAttention — IO-aware exact attention that's 2-4× faster; (4) Mamba (SSM) — attention-free architecture with linear-time inference; (5) RoPE — rotary positional embeddings enabling length generalization.

Mixture of Experts (MoE)

In a dense transformer, every parameter is used for every token. In MoE, the FFN layer is replaced by multiple "expert" FFNs, and a learned router activates only a sparse subset per token:

Sparse MoE Layer
y = Σi=1E G(x)i · FFNi(x)

Where:
E = total number of experts (e.g., 8, 16, 64)
G(x) = softmax(TopK(x · Wg)) — router weight for each expert
TopK = only the K highest-scoring experts are non-zero (typically K=2)
Each token uses only ~2/E of the total expert parameters
Think of a company with 8 specialists: one for math, one for writing, one for coding, etc. When a new project comes in (a token), the router sends it to the 2 most relevant specialists. '2+2' goes to math specialist. 'Write a poem' goes to writing specialist. Each specialist trains on their specific area, becoming deeply skilled.

Key benefits:

Parameter countTotal parameters can be 4-10× larger than a dense model at the same compute cost
Compute costFLOPs per token ~2/E × total — a 1T MoE model can cost as much as a 50B dense model
QualitySignificantly better perplexity per compute than dense models of equivalent active parameters
MemoryAll experts must be in memory despite sparse activation (key limitation)
Concrete routing example: Token 'cosine' → router scores: expert 3 (math): 0.7, expert 5 (vocabulary): 0.2, expert 1 (syntax): 0.1, expert 2 (entities): 0.0 → token processed by experts 3 and 5. The other 6 experts do nothing for this token.
📊 Model Size Comparison: Dense vs MoE

MoE models have far more total parameters but similar active (compute) cost to smaller dense models. GPT-4 is estimated to use an 8-expert MoE with ~1.8T total parameters but only ~350B activated per token.

Routing Challenges

MoE training introduces unique failure modes:

  • Expert collapse — all tokens prefer the same expert, defeating sparsity. Mitigated by auxiliary load-balancing loss.
  • Token dropping — if an expert is over capacity, some tokens get no expert computation. Mitigated by capacity factor (e.g., 1.2× ideal capacity).
  • Batch size requirements — MoE works best at scale. With few tokens per batch, load balancing is harder.

Auxiliary load-balancing loss adds a penalty proportional to the coefficient of variation of expert assignment:

Lbalance = α · E · Σi fi · Pi

Where fi = fraction of tokens routed to expert i, and Pi = average routing probability to expert i. When load is perfectly balanced, fi = Pi = 1/E and the loss is minimized.

Grouped-Query Attention (GQA)

The standard multi-head attention (MHA) uses h heads — each with its own Q, K, V projections → h sets of KV cache per layer. GQA reduces the number of KV heads while keeping all Q heads:

Attention VariantQ HeadsKV HeadsKV Cache SizeModels
MHA (multi-head)hhFullGPT-2, BERT
MQA (multi-query)h11/hPaLM, Falcon
GQA (grouped-query)hg (e.g., 8)g/hLLaMA 2/3, Mistral
Why can KV heads be shared without much quality loss? Because the keys and values encode 'what information is available at each position.' Multiple query heads asking different questions about the SAME content can share the same source material. Only the queries need to be different.

GQA with 8 KV heads reduces KV cache to 25% of MHA while maintaining nearly identical quality. It's the standard in post-2023 models. Each group of Q heads (e.g., 4 Q heads per KV head) shares the same K and V.

FlashAttention

Standard attention materializes the full n×n attention matrix in HBM (GPU memory), which is slow. FlashAttention computes attention in tiles that fit in SRAM (fast on-chip memory), never writing the full matrix to HBM:

  1. Load Q, K, V tiles into SRAM
  2. Compute partial attention scores S = QKT/√d in SRAM
  3. Apply softmax and multiply by V while still in SRAM
  4. Accumulate results and write back to HBM
Concrete analogy: Standard attention writes the full n×n matrix to main memory (HBM), then reads it back. It's like taking all your groceries out of the fridge, putting them on the kitchen table, then moving them to the counter one by one. FlashAttention keeps everything on the counter (SRAM) — you process each item without moving it to the table first.
Speedup: FlashAttention is 2-4× faster than standard attention for long sequences. More importantly, it's IO-aware — performance is bounded by SRAM→HBM bandwidth, not FLOPs. This makes long-context models practical (FlashAttention-2 achieves ~50% of theoretical HBM bandwidth utilization on H100).

Mamba: State Space Models

Mamba (2023) replaces attention entirely with a selective state space model (SSM). Instead of pairwise attention, the model maintains a hidden state that evolves over time:

Mamba SSM (discretized)
ht = Ā(xt) · ht−1 + B̄(xt) · xt
yt = C(xt) · ht

Where Ā, B̄ are discretized parameters that depend on the input xt
(this is the "selective" part — the state transition changes per token)
Mamba intuition: Mamba processes tokens sequentially, maintaining a 'summary state' as it goes. It's like reading a book and keeping a running summary in your head. After each sentence, you update your understanding. You never compare pairs of sentences directly — you just update your mental state. This makes it O(L) instead of O(L²), but you lose the ability to directly compare distant tokens.

Key advantage: inference is O(L) (linear in sequence length) instead of O(L²). For long sequences (1M+ tokens), this is transformative. Mamba-3B matches Transformer-3B on language modeling benchmarks while being faster at inference.

Trade-offs: Mamba doesn't have the same in-context learning capabilities as attention-based models at equal scale. Hybrid Mamba-Attention architectures (Jamba, Zamba) combine SSM layers for efficient processing with attention layers for recall-intensive tasks.

Other Notable Innovations

Multi-Token Prediction

Instead of predicting just the next token, predict the next n tokens simultaneously using multiple output heads. This provides a richer training signal and reportedly improves inference-time reasoning. Used in Meta's recent research.

NanoGPT-style Sparse Attention

Various approaches to sparsify attention — either by striding (attend to every Nth token), by windowing (attend to only nearby tokens), or by content-based sparsity (learn which tokens to ignore). Reduces O(L²) to O(L√L) or O(L).

Self-Play and REINFORCE-style Training

Models learning from their own generated trajectories (e.g., AlphaGo-style for reasoning). The model generates multiple reasoning paths, those that reach the correct answer are reinforced. This has driven major improvements in math and code reasoning.

What's Next?

The transformer architecture that defined the 2020s is undergoing rapid evolution. State space models challenge its dominance for long-context tasks. MoE enables trillion-parameter models without proportional compute. Hardware-aware algorithms (FlashAttention, kernel fusion) squeeze every bit of GPU utilization.

The next generation of LLMs will likely combine all of these: MoE × GQA × FlashAttention × SSM hybrids × multi-token prediction, all trained with massive-scale data pipelines and alignment techniques that go far beyond simple RLHF.

Speculative outlook: The frontier now includes test-time compute scaling (letting models 'think' longer), agentic LLMs that can use tools and act autonomously, and reasoning models that excel at multi-step problem solving through reinforcement learning on verifiable outcomes.
